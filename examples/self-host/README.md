# 小鲸鱼记忆系统 · 接入工具包

> **这个目录是什么**
>
> 这是「自己搭机器人」用的接入工具包：CLI、演示、提炼提示词、日记检索、定时备份，以及接进你自己 bot 的六个接入点。
>
> 它**和 DSH 插件共用同一份内核**（`../../lib/core/long-memory.js`），不是插件的第二份实现。区别只在接入方式：
> 插件由 DSH 宿主调用，记忆由 agent 用 `remember`/`recall`/`forget` 三个工具自己写；这里则给你命令行和代码入口，让你在自己的程序里调同一套函数。
>
> 装 DSH 插件请回到[仓库根目录](../../README.md)。

给聊天机器人用的长期记忆。一个 JSON 文件，一份共享记忆，会遗忘。

从 QQ 机器人「小鲸鱼」的生产环境里抽出来的，不是 demo 代码。核心模块 `../../lib/core/long-memory.js` 1000+ 行，零依赖，只 import `fs` 和 `path`。

```
node demo.mjs          # 看它怎么工作（不联网，10 秒）
node self-test.mjs     # 40 项自检
node cli.mjs status    # 体检测试库里有什么
```

## 它解决什么问题

普通聊天机器人的记性有两个极端：

- **只记上下文**：窗口一满就忘。昨天说的事今天要重新交代。
- **什么都存进向量库**：三个月后检索出一堆「上周要交的作业」，噪音比信息多。

这套东西走中间路线：**平时靠大模型提炼成一句话的事实卡，注入时按相关性挑，长期不用的自然淡出。**

## 三十秒上手

```bash
# 1. 加三条记忆
node cli.mjs add --text "阿风在准备考研，目标是本校计算机" --kind fact --weight 5 --tags 学业,考研
node cli.mjs add --text "阿风讨厌下雨天，出门必带伞" --kind pref --weight 3
node cli.mjs add --text "说好周六一起看电影《流浪地球3》" --kind promise --weight 4

# 2. 模拟一次对话，看会注入什么（注意每条的日期）
node cli.mjs render --query "周末有空吗"

# 3. 让模型去提炼（把输出贴回来）
node cli.mjs prompt --file chat.txt > ask.txt
#    ...把 ask.txt 发给任意模型...
node cli.mjs ingest --file model-reply.txt

# 4. 事情办完了就结案（不删数据，只是不再追问）
node cli.mjs done --text "说好周六一起看电影" --note "看完了"

# 5. 一个月后整理一次：过期的淡出、重复的合并
node cli.mjs organize --dry-run
node cli.mjs organize
```

默认库是 `./data/long-memory.json`，用 `--store` 指向别处。

## 八个设计决定

**① 一个桶，不分私聊和群聊**

记忆是这个角色本身的，不是某个聊天窗口的。在私聊里记住的事，群里也该记得——因为真正的活人只有一个脑子。

代价是隐私边界变弱。所以这套东西适合「一个主人 + 若干群」的个人机器人，不适合多租户 SaaS。见 [ARCHITECTURE.md](ARCHITECTURE.md#为什么只有一个桶)。

**② 冲突不静默合并，靠 `supersedes` 显式取代**

「阿风在准备考研」和「阿风在准备考公」字面相似度 0.9 以上。按相似度硬合并会把两条揉成一条，权重取最大值，之后永远淘汰不掉。

现在的做法：两条并存，由提炼时明确说「这条取代了那条」，旧的标记 `superseded`——**不删，留痕**。

**③ 检索用 BM25，不用字面重合**

字面重合在几十条时就会退化成「字多的靠前」，而且没有区分度概念（每条都出现的词和只出现一次的稀有词权重一样）。BM25 的 IDF 正好治这个。中文按相邻二字（bigram）切词，不需要分词词典。

**④ 注入时带日期**

模型没有「现在几点」的概念。一条记忆如果只有内容没有时间，「上周说的面试」和「上个月说的面试」在它眼里是同一件事。每条后面挂 `· 10-20`，跨年才给完整年份。

**⑤ 衰减，但只改状态不删数据**

按类型半衰期：事实 365 天、偏好 180 天、约定 30 天、事件 14 天。强度按**最后一次被想起**算，所以常被提起的事自动保持鲜活，从不被想起的才淡出。

淡出 = `status: archived`，原文一直在文件里，随时能捞回来。

**⑥ 主动提醒：会自己找话头**

约定/计划里带时间点的（「这周六看电影」「下周交作业」），提炼时抽出 `dueAt`。到了时候，机器人收到消息时顺手问一句「有件事之前约好了…现在怎么样了？」，提醒后结案、不反复追问。活人会自己找话头，记忆系统也该会。

**⑦ 归档护栏：防手滑**

衰减归档每次最多沉 `maxArchivePerRun`（默认 3）条，按强度从弱到强取最弱的。防止某天参数被改错、或误触整理时，一次性把几十条全归档成「失忆」。被挡下的条数会返回 `deferred`，方便发现异常。

**⑧ 结案，不是删除**

约定兑现了、面试有结果了，标 `resolved`——**不删，也不再当待办追问**，但仍然留在检索库里。聊到「上次那个电影」，她还答得上来。

这是和「取代」分开的第二种终态：取代 = 这条信息不再成立（考研改考公），结案 = 这件事真的做完了。混成一个状态，回复就会把办完的事当没办过，或者反过来把作废的信息当现状。

完成的事不参与衰减（结案是「有结果」，不是「不重要」），但容量吃紧时排在生效条目之前被清。

## 命令

| 命令 | 干什么 |
|---|---|
| `status` | 总览：分类、强度范围、文本长度、命中分布 |
| `list [--status active\|resolved\|archived\|superseded\|all] [--kind fact]` | 列条目，含结案/归档/已取代、跟进日期 |
| `render [--query 文本]` | 生成注入块，会记录本次命中 |
| `prompt [--file chat.txt]` | 生成提炼提示词（每行「昵称：内容」） |
| `ingest [--file reply.txt]` | 解析模型输出并写入 |
| `add --text "..." [--due "2026-11-01"]` | 手工加一条，可设跟进时间 |
| `done --text "..." [--note "过了"]` | 结案：不再追问，但仍可检索 |
| `forget --text "..."` | 物理删除（慎用） |
| `organize [--dry-run]` | 衰减归档 + 重复合并 |
| `due` | 列出到期还没提醒的跟进项 |
| `doctor` | 找问题：过长、多事件、无标签、重复、从未被想起 |
| `export [--out x.md]` | 导出可读清单 |
| `why --query "..."` | 看检索打分，回答「为什么这条没被想起」 |

## 数据长什么样

```json
{
  "version": 2,
  "buckets": {
    "shared": [
      {
        "id": "lm-mg3k2a1f",
        "kind": "fact",
        "text": "阿风在准备考研，目标是本校计算机",
        "tags": ["学业", "考研"],
        "weight": 5,
        "status": "active",
        "dueAt": null,
        "remindedAt": null,
        "createdAt": 1761570000000,
        "lastUsedAt": 1761656400000,
        "updatedAt": 1761570000000,
        "hits": 7
      }
    ]
  }
}
```

`status` 四个值：`active`（生效）/ `resolved`（已完成）/ `superseded`（被新信息取代）/ `archived`（自然淡出）。

`active` 和 `resolved` 都能被检索、能进注入块（后者带「已完成」标记），`superseded` 和 `archived` 不再出现。

## 它不能做什么

- **不理解语义**。BM25 是字面检索。「我心情不好」检索不到「她最近压力大」，除非标签里写了。
- **主动提醒只覆盖「有时间点」的事**。`dueAt` 能管「周六看电影」「下周交作业」，但管不了没有明确时间的关切（「你妈身体最近怎么样」）。那种要靠语义检索，见下一条。
- **不适合多用户隔离**。单桶设计，所有人的记忆混在一起。
- **提炼质量取决于模型**。解析器能容忍格式漂移，但模型如果只输出「好的」两个字，它也无能为力——这种情况会明确报解析失败，不会静默丢数据。

## 运维配套：日记、备份

本包除了核心记忆模块，还带两个独立运维脚本，跟长期记忆配合成完整闭环：

- **日记层**（`scripts/diary.mjs`）：长期记忆会衰减，想不起的事得有个不衰减的兜底。日记按天沉淀、永不删、可关键词搜，用 `diary.mjs --search "考研"` 翻旧账。日记的**自动生成**在 `src/bridge.js`（每天凌晨汇总当天会话让模型写一页），本包提供**查看/检索**入口和检索所需的 `tokenize`/`buildIndex`/`bm25Scores`。
- **定时备份**（`scripts/backup-state.mjs`）：备份长期记忆、会话、交接回忆、黑话、配置等关键状态，保留 7 天滚动清理。独立于主程序——**主程序挂了备份也能跑**，这是备份该有的样子。

```bash
node scripts/backup-state.mjs              # 备份到 backups/state，保留 7 天
node scripts/backup-state.mjs --dry-run    # 先看看会备份什么
node scripts/diary.mjs                     # 列出所有日记
node scripts/diary.mjs --search "考研"     # 按关键词搜日记
```

## 从哪来

这套东西在生产里跑了两周多，21 条记忆、7 天数据。开发过程中踩过的坑，都写进代码注释和测试里了：

- 提示词要 `text`、解析器只认 `content`，导致后台提炼 14 次全部静默丢数据
- `STATUS` 常量漏了 `archived`，归档状态写盘再读回就复活，整理等于白做
- 记忆条数少于注入上限时，所有条目每次都被记成「刚被想起」，衰减永远不生效

三个 bug 的共同点：**都不报错**。所以这套代码的原则是——**宁可报错，不要静默降级**。解析失败就明确失败、留着重试；归档就写清归档时间；命中只算真正沾边的。
